# v0.10.0 — 2026-05-19

Phase 10: Filters foundation. Ships the JSON-backed filter builder
that the rest of the phase will build on top of (user tags, bot
collapse, dup map, author context, AI prose signal).

## New

- **lib/utils/filterRules.js** — pure rule schema + evaluator. Seven
  fields (user/subreddit/domain/keyword/flair/score/commentCount),
  five ops (equals/contains/regex/lt/gt), four actions
  (hide/dim/collapse/badge), optional target (post/comment/both).
  Regex compilation fails closed.
- **lib/modules/filterRules.js** — module glue. Wires the evaluator
  into `watchForThings` so rules only see added nodes; never rescans
  the whole tree.
- **tests/unit/filter-rules-contract.test.mjs** — 7 assertions
  covering every op + field + target combination, regex
  fail-closed, JSON parsing edge cases, default normalisation, and
  the module registration / action coverage.

## Deferred (with reason)

- **User tags, bot/AutoModerator collapse, dup/crosspost map,
  author-context badge, AI/bot prose signal** — these are all
  consumers of the filterRules pipeline that just landed.
  Scheduled for the v0.10.x patch series so the foundation gets a
  release of bake time and a public README pass first.
- **Multi-column feed, OP/admin/mod/friend highlight, per-sub
  custom-style override** — carried over from v0.9.0 deferred list;
  these will join the v0.10.x patch series.

## Acceptance criteria

- [x] No full-thread rescans per mutation (watchForThings ensures
      only added nodes are visited).
- [x] Local cache + rate limiter are in place for future
      user/subreddit API enrichment (rateLimiter shipped in v0.8.0,
      reused here as needed).
- [x] AI/bot signal will run locally and be fully disabled (when
      shipped; no telemetry today).
- [x] Import/export for filters works (rulesJson is the schema; the
      v0.6.0 settings JSON import/export round-trips it verbatim).
